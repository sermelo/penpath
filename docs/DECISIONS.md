# Decisions

- 2026-11-23 — LUC-30 likeness scoring: keep SSIM via scikit-image (greyscale, 256x256, blur sigma 1.5) as the measure; widen numpy from `>=1.26,<2` to `>=2.4,<3` so Python >=3.14 installs a compatible wheel instead of source-building unsupported numpy 1.26 on CI (sergio approved via confirmation card 64e0f31d); use pixels-per-millimetre (default 96/25.4) as the single scale unit shared by `compute_likeness` and `simulate_plot`.
- 2026-11-23 — LUC-31 CLI preview/evaluate: use that single pixels-per-millimetre unit for both the simulation and the likeness crop (no second "dpi" unit); `evaluate --json` writes only the JSON object to stdout and sends human tables to stderr so scripts can pipe it straight into `jq` (Architect direction in LUC-31).
- 2026-11-23 — LUC-41 SVG parsing: treat `<polygon fill="none">` as a closed polyline whose length includes the closing edge back to the first point; keep skipping polygons with a fill, since those are shapes rather than strokes, so vpype output is fully visible to the simulator.
- 2026-11-23 — LUC-42 vpype placement: scale image geometry into the `fit_image_placement` rectangle with the direct export's `_scale_geometries_to_placement` helper before handing it to vpype in pixels, drop `--center` when a placement is given so vpype cannot move the ink, and write the pen width via vpype's `penwidth` command so previews use the real stroke width; callers without a placement keep the old centred behaviour.
- 2026-11-23 — LUC-43 machine cost: `parse_svg_strokes` gains opt-in `include_pen_up` (default false) that inserts a straight two-point travel stroke between non-contiguous strokes when the gap exceeds 0.01 mm, using the following stroke's colour and width; `compute_machine_cost` counts `num_strokes` for pen-down strokes only; `penpath evaluate` opts in so travel and lifts are real, while `preview` and default library calls are unchanged.
- 2026-11-23 — LUC-44 vpype pen identity: write each pen's colour and Inkscape layer label into its vpype layer with `color --layer <id>` and `name --layer <id>`, sourcing both from the same `Pen` and the shared `_pen_layer_label` helper used by the direct export; vpype normalises CSS colour names to hex, so the two paths agree on colour semantically rather than textually.
- 2026-11-23 — LUC-46 seed propagation: `PFMSettings.to_typed_settings()` now unwraps the nested `settings` payload (as `SketchLinesPFM` uses) before building the typed settings model, so `-s seed=42` reaches the algorithm; flat PFM layouts pass through unchanged and `seed` still defaults to `null`. This makes scores from `penpath evaluate` comparable between runs of the same command.
- 2026-11-23 — LUC-49 convert output path: the optional positional `OUTPUT_PATH` and `-o/--output` are equivalent ways to name the SVG; when both are given, compare the normalised paths and accept only equal paths, otherwise fail with a usage error (exit 2) naming both. The optional vpype dependency is the `vpype` extra, so the install hint is `pip install "penpath[vpype]"`; vpype stays optional and the CLI falls back to direct SVG export without it.
- 2026-11-24 — LUC-51 D5 profile schema: `MachineProfile` and its section models validate the agreed bed/feed/pen/gcode/pen_change shape, forbid unknown keys so typos fail loudly, and check that Z heights are ordered, a ramp has both touch and hover, nozzle ranges increase and each pen-change step has one action; the schema holds no file I/O and no machine values.
- 2026-11-24 — LUC-51 D2 (machine profiles): the profile is the only home for machine values; `core/profiles.py` holds the schema and no numbers, and built-in profiles are YAML data under `presets/profiles/` read with `importlib.resources` (LUC-51 plan revision 2).
- 2026-11-24 — LUC-51 D3 (user profiles): a person keeps their own machines in one YAML file at `$XDG_CONFIG_HOME/penpath/profiles.yaml` (or `~/.config/penpath/profiles.yaml`), a mapping of names to profiles; a user profile overrides a built-in of the same name and `list_profiles()` lists the sorted names of built-ins and user profiles, each name once (LUC-51 plan revision 2).
- 2026-11-24 — LUC-76 basic-shape fixtures: the six 64x64 shapes are plain-text PBM (P1) files, one file per shape, generated by a NumPy script, because the working agents cannot read raster images; they are test data only and are not added to `SUPPORTED_FORMATS`.
- 2026-11-24 — LUC-50 D3 (palette model): `Palette(name, pens)` holds pens in drawing order; `Project.pen` is optional, `Project.pens` is the ordered list, and `Project.palette` returns `pens` or the single `pen`, so old project files keep working and `Pen.name` is the layer label.
- 2026-11-24 — LUC-50 D4 (CLI and YAML surface): `--palette` accepts a built-in name or `name=width,#hex;...`, is exclusive with `--pen`, and YAML accepts `palette:` or `pens:` but never together with `pen:`; palette order is drawing order and a user list is used exactly as given.
- 2026-11-24 — LUC-50 D5 (Stabilo palette): the built-in `stabilo_88` palette has twelve 0.4 mm pens named `stabilo_88_<colour>` in light → dark order, with approximate hex values in one table in `presets/palettes.py`; `penpath info palettes` shows that order.
- 2026-11-23 — LUC-53 erase model: a drawn segment adds `int(erase_min + y_progress * (erase_max - erase_min))` to each pixel it covers, saturating at 255, with `y_progress = 0.5*x^3 + 0.5*x` and `x = luminance/255`; defaults `erase_min=50`, `erase_max=125`, `tone=0.5` match DrawingBotV3, so dark areas keep receiving ink while light areas stop early.
- 2026-11-23 — LUC-53 endpoint rule: a candidate ray ends at the pixel where the running mean luminance of the sampled prefix is lowest (only prefixes longer than `min_length` qualify); reaching the image edge ends the ray at its last in-bounds pixel instead of counting a failure, and every emitted coordinate is clamped inside the image.
- 2026-11-23 — LUC-53 stop condition: drawing stops when `(mean - initial) / ((253.5 - initial) * line_density) >= 1`, not on an invented line count; `line_density` defaults to the reference 0.75 and shading defaults off. With `erase_enabled=False` the image never lightens, so a hard stroke cap (200 for normal images) ends the run and the result is deliberately dense and dark.
- 2026-11-24 — LUC-53 gate: part 1's published SSIM floors were asserted verbatim first and measured with part 1's harness unchanged (vpype 1.15, seed 42): SSIM circle 0.5681, gradient 0.5051, sphere 0.8362, face 0.6189, photo 0.2064, all below 0.75/0.80/0.88/0.70/0.75; sphere ink share 0.0002 < 0.0003 and photo tone ratio 1.59 < 2.0 also failed. The Architect withdrew those floors in LUC-47 because they measure a raster stipple (the ideal scores 0.99) and asked for 84-99% of its ink.
- 2026-11-24 — LUC-53 erase brush: port DrawingBotV3's round erase brush (`PFMRenderPipe.eraseGeometry` with a round-capped stroke); `erase_radius_min` and `erase_radius_max` are brush radii in image pixels (reference Register defaults 1/1), interpolated by the same tone curve as the erase amount and applied once per covered pixel per segment.
- 2026-11-24 — LUC-53 stop condition: drawing stops on luminance progress `(mean - initial) / ((253.5 - initial) * line_density) >= 1`, not on a counted line limit; with `erase_enabled=False` the image never lightens, so a hard stroke cap ends the run and the result is deliberately dense and dark.
- 2026-11-24 — LUC-53 start-angle rule: draw the random ray start angle per segment, as `PFMSketchLinesBasic.nextPathFindingResult` does, not once per squiggle; `angle_range` accepts negative angles in [-360, 360] as the reference does.
- 2026-11-24 — LUC-53 line-length and angle-test defaults: adopt the registered reference values `min_length=2` px, `max_length=40` px and 20 angle tests (`search_angle_step=18` degrees), replacing 10/100 px and 72 rays; the default start-angle band is the reference's -72..-52 degrees.
- 2026-11-24 — LUC-53 squiggle noise: the reference has no perpendicular segment noise, so `squiggle_enabled` now defaults to false and stays only as an opt-in penpath addition.
- 2026-11-24 — LUC-53 erase calibration: keep the reference's erase-curve shape and calibrate its values for penpath's image-pixel scale to `erase_min=35`, `erase_max=80`, `tone=0.5`, brush radius 1/1 and `squiggle_min_length=50` (reference 50/125 and 25), measured with part 1's harness; this keeps the gradient's ink spread and the sphere's ink share above their floors.
- 2026-11-24 — LUC-53 zero-length rays: a candidate ray whose only in-bounds pixel is its start reports white so it cannot be chosen as the darkest endpoint; a short ray that reaches the border keeps its last in-bounds pixel and running mean. Without this, a black pixel on the image corner wins with a zero-length ray and the whole drawing is empty.
- 2026-11-24 — LUC-53 squiggle end: reaching the image edge or the darkness limit ends the squiggle and keeps the segments already drawn; it no longer marks the stroke as failed and discards it. This is the reference's path-termination rule and it stops small images from producing no lines.
- 2026-11-24 — LUC-53 measured result after the fidelity fixes (part 1 harness, seed 42): SSIM circle 0.5474, gradient 0.5401, sphere 0.8135, face 0.6481, photo 0.5099; every re-derived floor and every non-SSIM floor passes. The photo now scores above its blank page (0.4993). Gate wall time 14:13 / CPU 11:39 on a shared runner, above part 1's 7.3 min budget; reported to the Architect, who owns the CI budget.
- 2026-11-24 — LUC-53 gate floors: withdraw the part 1 SSIM floors 0.75/0.80/0.88/0.70/0.75 and enforce the re-derived 0.53/0.46/0.79/0.57/0.18. Rule: `max(blank, random) + 0.05`, never below `measured - 0.05`; where a drawing cannot beat both trivial baselines, `random + 0.05` and the non-SSIM floors carry the quality. Part 1's non-SSIM floors stay verbatim: covered width and height >= 0.60, bbox area >= 0.40, ink per 4x4 cell >= 0.0003, dark/light tone ratio >= 2.0. The withdrawn floors remain in docs/TESTING.md as the raster-ideal target and the reason for the change.
- 2026-11-24 — LUC-53 breaking change: `line_density` changes meaning from lines per millimetre to an ink-density multiplier in the luminance-progress stop rule; `min_length` and `max_length` are now image pixels, not millimetres.
- 2026-11-25 — LUC-54 final defaults: ship the LUC-53 calibrated Sketch Lines defaults unchanged — `line_density=0.75`, `min_length=2`, `max_length=40`, `angle_range=(-72,-52)`, `search_angle_step=18`, `sample_step=10`, `erase_min=35`, `erase_max=80`, `tone=0.5`, brush radius 1/1, squiggles and shading off, `max_strokes=auto`. No algorithm or default-value change in part 3. Re-measured 2026-11-25 with part 1's harness unchanged (vpype 1.15, seed 42): SSIM circle 0.5474, gradient 0.5401, sphere 0.8135, face 0.6481, photo 0.5099, each above the enforced 0.53/0.46/0.79/0.57/0.18 floors; `pytest tests/integration/test_sketch_lines_gate.py` is green.
- 2026-11-25 — LUC-54 presets: all eight built-in PFM presets stay as style choices and only `default` is calibrated against the likeness gate. `squiggly` sets `erase_enabled=false`, so the working image never lightens and a hard stroke cap ends the run; it is a deliberately dense, dark decorative scribble, not a photo likeness, and is exempt from the SSIM gate. `fine`, `bold`, `shaded`, `crosshatch`, `hatch_horizontal` and `hatch_vertical` keep erasing on and are likewise out of the gate's scope. `-s KEY=VALUE` overrides any preset key, and an invalid key or value now exits 2 naming the setting instead of printing a traceback.
- 2026-11-25 — LUC-50 D6 (colour separation): `separate_palette` assigns every pixel of the loaded colour image to its nearest pen by Euclidean distance in CIE Lab (`skimage.color.rgb2lab`), returning one full-size `L` image per pen in pen order, with the pixel's luminance on the pen's own pixels and white elsewhere; the caller splits before the filter pipeline so the default `grayscale` step cannot erase the colour first.
- 2026-11-25 — LUC-50 D7 (per-pen drawing): `convert` splits the working colour image once, then runs the filters, the PFM and `optimize()` once per pen, so simplify → merge → sort never sees lines from two pens; `export_pen_layers` maps each pen's pixels into the shared placement and `write_penpath_svg` numbers only the pens that drew, in palette order. vpype still gets one call per pen, and penpath still writes the final SVG on both paths.
- 2026-11-25 — LUC-55 working resolution: draw at `paper_longest_side_mm / pen_width_mm` pixels on the longest side, clamped to 256–1024 px, never enlarging and keeping the aspect ratio; `--max-resolution` replaces the derived value without clamping, `--no-downscale` keeps the source pixels, and the chosen size goes to stderr and to `image-width`/`image-height` plus `source-width`/`source-height` in the placement metadata. Pixel-valued Sketch Lines settings (`min_length`, `max_length`, `sample_step`) scale by the same factor and clamp to their model ranges; a missing field fails loudly rather than silently drifting.
- 2026-11-25 — LUC-50 D1 (SVG layout): every penpath SVG uses millimetres for user units, so `width`/`height` and `viewBox` are in mm, the placement mapping no longer multiplies by 96/25.4, `stroke-width` is the pen width in mm, and the background is a plain rect as a direct child of `<svg>` rather than a layer. `parse_svg_strokes` derives its mm-per-unit scale from the root width/viewBox ratio, so preview, evaluate and likeness read both old and new files correctly.
- 2026-11-25 — LUC-50 D2 (final writer): penpath writes the final SVG on both export paths. vpype optimises geometry only, one call per pen with a single layer per call so nothing merges or sorts across pens; its output is read back with `parse_svg_strokes` (in mm) and passed to the same `write_penpath_svg` the direct export uses. `--no-vpype` keeps `optimize()` per pen.
- 2026-11-25 — LUC-50 D8 (vpype gotcha): `vpype read` takes the layer number from the digits in `inkscape:label`, so labels such as `stabilo_88_red` and `stabilo_88_green` both read as layer 88 and merge. Penpath keeps `id="layerN"` in pen order and documents that consumers must read the SVG with an XML parser instead of feeding it back to `vpype read`.
- 2026-11-25 — LUC-59 D3 (profile listing): `penpath info profiles` lists every built-in and user machine with its source (`built-in` or `user`), description, bed size and feeds; `list_profile_sources()` is the core function behind the listing and a user profile still overrides a built-in of the same name (LUC-51 plan revision 2).
- 2026-11-25 — LUC-59 D5 (profile format docs): `docs/CLI.md` carries a complete, loadable example profile, every D5 field and the placeholder list (`{pen}`, `{pen_index}`, `{pen_count}`, `{layer_index}`, `{layer_count}` plus profile scalars in code blocks); code blocks stay verbatim machine-space G-code with no coordinate placeholders (LUC-51 plan revision 2).
- 2026-11-25 — LUC-59 D6 (coordinates): the docs state that the SVG page is millimetres from its top-left with Y down, `page.origin_mm` and `pen.touch_xy_mm` are pen space, emitted G-code is nozzle/machine space with `nozzle = pen - pen_offset`, and `reachable_corner` puts the page bottom-right at the drawable area's front-right corner (LUC-51 plan revision 2).
- 2026-11-25 — LUC-80 line sort: compute each line's endpoints once into numpy arrays, scan start/end distances with `np.hypot` in an interleaved array so `argmin` keeps the old tie-break (earliest line, start before end), and judge each 2-opt reversal by the two adjacent link deltas, refreshing the running total only on acceptance (lines are reversed, never reordered). The exact order is preserved: 3000 synthetic and 80 random lines matched the old algorithm endpoint-for-endpoint, and `penpath convert tests/fixtures/images/reference/face.jpg -o /tmp/face.svg --pfm-setting seed=42` produces a byte-identical SVG (sha256 `6565353e...`, 3133 sorted strokes), so travel distance and the stroke set are unchanged without needing the "not worse" fallback. Measured on this runner: sorting 3000 synthetic lines went from 352.2 s wall / 209.4 s CPU before to 1.19 s wall / 0.44 s CPU after; the full convert went from 1595.6 s wall / 1134.2 s CPU before to 30.8 s wall / 30.4 s CPU after (the before run shared the runner with the baseline sort benchmark, so its wall time is inflated; CPU time is the comparable figure).
- 2026-11-25 — LUC-56 part 2 progress: `convert` reports each finished pipeline stage to stderr, keeping a live `rich` bar on a terminal but writing one flushed `[n/N] name... done in X s` line per stage when stderr is redirected, because `rich` prints nothing on a non-terminal. The bar is non-transient so the final summary stays on screen; stages are load, optional downscale, filters, drawing, geometry and export, followed by total time and the saved-SVG line. `--quiet`/`-q` silences all of that but never errors, and stdout stays empty in every case.
- 2026-11-25 — LUC-75 basic-shape fixtures: render each 64x64 PBM to 400x400 with nearest-neighbour before the pipeline runs, so the drawing algorithm sees the same pixel scale as the reference image set (the black square's ink purity is 0.56 at 64x64 and 0.99 at 400x400); the CLI needs a PNG twin because it does not read PBM.

- 2026-11-25 — LUC-48 part 3 budget: a 12 MP photo (4080x3072) on 190x190 mm paper with a 0.4 mm pen converts in under 30 s on the VPS; measured 11.49 s (load 0.15, downscale 0.23, filters 0.00, PFM 3.89, geometry 5.44, export 1.78), 13.09 s on the busy shared VPS, 21.32 s with five concurrent jobs.
